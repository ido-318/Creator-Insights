# הגשת פרויקט הגמר — Creator Insights

## היקף ההגשה

שני צוותי CrewAI, שלושה סוכנים בכל צוות, עם שער בדיקה בקוד ביניהם ודשבורד Streamlit בעברית. המטרה היא ניתוח מעורבות, השוואת מודלים והצגת מגבלות. הצלחת הריצה אינה הבטחה לחיזוי מדויק: יש להציג גם תוצאה שבה המודל אינו עוקף את קו הבסיס.

Supabase הוא הרחבה אופציונלית ואינו תנאי להרצה או להגשה המקומית.

## הדגמה חיה מקצה לקצה

1. הכינו את Python 3.13, התלויות, קובץ הנתונים ו־`.env` לפי [README](../README.md). אין להציג או לשתף את המפתח.
2. הפעילו `python -m streamlit run app.py`, היכנסו בקוד המקומי ופתחו את מסך המערכת.
3. הפעילו פעם אחת את ההרצה המלאה. זו קריאה אמיתית ל־Claude, שעשויה להיות כרוכה בתשלום. אין צורך ב־Supabase.
4. הציגו את צוות הניתוח, בדיקת החוזה והטביעות, ואחריהם את צוות המידול. המתינו לסטטוס `completed` בקובץ `artifacts/flow_<id>.json`; סיום תהליך לבדו אינו מספיק.
5. הציגו את התובנות, תוצאות ההערכה והסקירה בעברית. השוו MAE של המודל לקו הבסיס והסבירו את מגבלות המדגם והחשיפה לסט הבדיקה בזמן הפיתוח.
6. הציגו בדיקת עצירה מכוונת באמצעות `python test_flow_failure.py`: שעה לא חוקית צריכה לחסום את צוות המידול. הבדיקה משתמשת בעותקים זמניים ובצוותים מדומים, ואינה תחליף להרצה החיה.

אפשר להריץ את אותו Flow גם ב־`python project_flow.py`. לצורך הגשה, שמרו את מזהה הריצה, זמן הריצה, תוצאת האימות והמדדים, וציינו אם ההדגמה בוצעה דרך CLI או דרך הממשק. אין להגיש לוג עם סודות.

אם סביבת הרצה מגבילה כתיבה לתיקיית הפרויקט, ניתן להגדיר לפני ההרצה:

```bash
export CREWAI_STORAGE_DIR="$PWD/.runtime/crewai"
export MPLCONFIGDIR="$PWD/.runtime/matplotlib"
python project_flow.py
```

אלה קבצי ריצה מקומיים, שאינם חלק מההגשה. אין להפעיל שתי הרצות מלאות במקביל.

## עבודה בענפים ו־PR

כל פיצ׳ר חדש יפותח בענף נפרד ויוגש ב־PR עם תיאור השינוי והבדיקות. תיקוני תיעוד יכולים להישאר ב־PR תיעוד אחד. אין לפצל בדיעבד את ההיסטוריה כאילו פיצ׳רים ישנים עברו PR נפרד.

נכון להכנת ההגשה, ענף ברירת המחדל הוא `feature/crewai-flow`. יש לבחור במפורש את ענף היעד ל־PR ולבדוק את ההבדלים לפני המיזוג; אין להניח שהיעד הוא `main`.
